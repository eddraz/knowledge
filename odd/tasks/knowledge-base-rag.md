# Feature: knowledge-base-rag

RAG knowledge base in Rust: SQLite + sqlite-vec (vector KNN, cosine) + FTS5 (lexical),
embeddings via bge-m3-Q8_0.gguf through a llama-server sidecar, grounded answers
generated by LFM2.5-230M-F16.gguf sidecar. CLI interface (`knowledge add|ask|search|list|rm`).

## Locked decisions (2026-09-20)

- Storage: sqlite-vec `vec0` virtual table (f32[1024], cosine) — NOT corpus-in-RAM brute force.
- Lexical: FTS5 `unicode61 remove_diacritics=2`. LIKE only for exact matches.
- Embeddings: bge-m3-Q8_0.gguf via upstream `llama-server --embedding` sidecar (verified: dim 1024, L2-normalized).
- Generator: LFM2.5-230M-F16.gguf via `llama-server` sidecar (K2-Horizon rejected for RAG: reasoning length too slow on target CPU).
- Interface: CLI (clap). Sidecars spawned/supervised by the app itself.
- Grounding contract: score gate (below threshold -> "not in knowledge base") + prompt restricted to context only.
- Chunking: ~400-800 chars, ~15% overlap, sentence/paragraph boundaries, configurable.
- Same model indexes and queries: bge-m3 only. Never mix embedding spaces.
